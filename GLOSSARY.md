# Glossary

The names this project uses for its own things. Code, docs and reviews use them. The code name is in brackets where it differs.

## The flow

- **Record bar** (`src/pages/RecordBar.tsx`, `windows/bar.rs`): the pill at the bottom center of the screen, just above the Dock. In setup it has Quit, the mode, camera and microphone, and Settings. While recording it shows the timer, Restart, Pause and Stop.
- **Mode:** what you're about to record: a display, a window or an area.
- **Picker** (`src/pages/Picker.tsx`, `picker/`): what opens after you choose a mode. It puts one overlay on each display and lets you point at the target.
- **Overlay:** the see-through window the picker places over one display. It draws the highlight or the Area box. Overlays are made once, then hidden and shown, never closed.
- **Picker session** (`Session`): what's being picked, sent whole from Rust to every overlay whenever it changes: the mode, the sources, the pinned window and the display holding the Area box. Rust works out each window's display and each display's scale once, so the overlays never derive them.
- **Sources:** the displays and on-screen windows the picker can pick from.
- **Highlight:** the orange outline on the display or window under the pointer, with everything else dimmed.
- **Pinned window:** a window chosen with Tab. It wins over the pointer until the pointer moves.
- **Area box** (`AreaBox`): the box you drag out in Area mode, with eight handles.
- **Capture bar** (`CaptureBar`): the pill on the highlighted target. It shows the capture tile, what will be recorded, its size in pixels, the Area's ratio chip, and Record. Every mode shares it.
- **Capture tile** (`CaptureTile`): the 40px square at the left of the capture bar: the window's app icon, or an icon for the mode.
- **Ratio chip** (`RatioChip`): the Area's control on the capture bar. Its menu locks the box to 16:9, 4:3, 1:1 or 9:16.
- **Safe top** (`safeTop`): how far down from a display's top things stay clear of the menu bar and the notch, in points. The capture bar and the ratio menu keep below it.
- **Target:** exactly what will be recorded: a display, a window, or an area of a display.
- **Record (a target):** the picker's last step. It closes the overlays and starts recording the target.
- **Frame:** while an area or a window records, the overlay on that display stays up as the frame. It's click-through, has no controls, and dims everything but what's recorded. Not to be confused with `geometry::Frame` (a rectangle in points, and the generated `Frame` type), a video frame, or the editor's framed recording (`frameLayout`, and appearance sizes measured on a 1920-wide frame).
- **Recording status** (`RecordingStatus`): the one copy of the recording's state, owned by Rust. It holds the phase, the time recorded and the last error. The record bar shows it and keeps no copy.
- **Phase:** where the recording is: idle, starting, recording, paused or stopping. `next_phase` in `recording.rs` decides which action is allowed when.
- **Pause:** frames captured while paused are left out, so the file plays straight through.
- **Pause timeline** (`capture/timeline.rs`): a recording's time with its pauses cut out, on the clock ScreenCaptureKit stamps frames with. The bar's timer and the video agree because both use it. Not the editor's timeline.
- **Restart:** throws away what's been recorded and records the same target again, after a native alert. It pauses while asking, so the alert never ends up in the recording.
- **Recording preview** (`src/pages/RecordingPreview.tsx`, `windows/preview.rs`): the card in the bottom-left corner after you stop. It loops the clip. Hover shows the clip dock. The record bar hides while it shows.
- **Clip dock** (`ClipDock`): the morph pill at the bottom of the preview. It holds Save, Copy and Edit, then morphs to Saving, Copied, Saved with Show in Finder, or an error.
- **Current recording** (`current_recording.rs`): the recording you've just made, named for when it started ("2026-10-16 07.41.28"). It waits in app storage while the preview and then the editor show it. It keeps, saves, copies, edits and closes itself, and each step decides which window shows: the bar, then the preview, then the editor. Save exports an `.mp4` to the save folder (Downloads unless Settings says otherwise). Nothing is kept: closing deletes it, so Save or Export is the only way to keep it.
- **Close (the preview or editor):** brings the bar back and deletes the recording and its project file. Unless it was saved or exported to a file, it asks first: the preview offers Save and close or Discard, the editor Export and close (the page runs the export, then closes) or Discard.
- **Editor** (`src/pages/Editor.tsx`, `windows/editor.rs`): where Edit in the preview takes the recording. It's being rebuilt one piece at a time: the stage, the timeline with zoom and speed regions, the Background panel and Export. `bun run dev:editor` opens your newest recording that has a cursor log, in place, so its edits and clicks are real. `EDIT_VIDEO=/path/to/video.mp4 bun run dev:editor` opens any video instead, copied into one folder per video.
- **Stage:** the editor's big view of the recording, framed the way it will export.
- **Appearance** (`Appearance`): how the editor frames the recording: background, padding, corners, inset, shadow and border. Sizes are measured on a 1920-wide frame, so an appearance matches at any size. The Background panel edits it, and the stage and export both draw it.
- **Fill** (`Fill`): the background behind the recording: a gradient, a color, or an image. Fill → Image's drop zone takes a picture dropped anywhere on the editor or picked with browse (PNG, JPEG, HEIC or WebP), and `add_background` copies it beside `project.json` as `background.png`, `background 2.png` and so on, so the project stays self-contained and undo can go back to an earlier picture. The fill keeps only that file name (`fill.image`). The picture covers the frame from its center, like CSS `cover`, on the stage and in the export (`cutout`); with no picture yet, the Image tab shows the gradient.
- **Timeline:** the editor's strip under the stage: the toolbar (play and pause with Space, the time), then the ruler, the Recording track and the lanes, with the playhead across them. Labels on the ruler sit at least 96px apart.
- **Cut:** a split in the Recording track, shown as a 6px gap between two clips with a scissors disc on it.
- **Cursor** (`lib/editor/cursor.ts`, `export/cursor.rs`, `macos/cursor.rs`): the cursor drawn over the recording from its cursor log (`events.jsonl`), since capture leaves the real cursor out. Capture also logs when a key was pressed (never which key; `{"type":"key"}`, from the macOS key-press count, no permission needed) and which macOS cursor was showing, kept to the simple ones (arrow, hand, text beam; anything else counts as the arrow, Aidan Oct 25) every 100ms, by matching the system cursor's picture. The stage and export draw the real macOS cursor pictures (`cursor_images`), scaled so 100% is 3.375 times real size (`CURSOR_SCALE`; Aidan, Oct 25: the old 75%). Styles (`CURSOR_STYLES`, picked from tiles in the Cursor panel): macOS (the real pictures), Pointy, Rounded, No stem (an arrowhead) and Dot. Each drawn style has its own arrow, hand and text beam (`SHAPES` in `cursor.ts`, vector paths with a hotspot each), plain black with a white edge and no shadow, written at 8× their size; Dot is a circle for every shape. A saved project with a removed style falls back to macOS. Always use pointer keeps the arrow everywhere. `cursorPath` simulates where it is at every moment: a smoothing spring with an optional hover lead, tilt on a looser spring, a static angle, a press dip while the button is held, fading when still, shake removal, looping back to exactly where it started and stopping before the end. The cursor mode (`appearance.cursor.mode`, lines in `CURSOR_MODES`) is Hidden, Plain or Styled; Plain (`plainOr`) turns all of that off and shows the real cursor 1:1, and Hidden draws nothing. The settings live in `appearance.cursor`, and the Cursor panel draws them from `CURSOR_SECTIONS` through `SettingControl`: outside Styled the sections dim to 40% and take no input, Advanced is folded by default, a setting with `onlyWith` shows only while that switch is on, and `help` shows as a tooltip on the label. The cursor is drawn in its own layer above the recording, so it can overhang the frame, and hides when its tip leaves the visible recording. It is not inside the zoom's `transform: scale()`: `Cursor` applies the zoom to its own position and size, so the browser draws it at its final size instead of stretching a layer (that stretch made it blurry).
- **Kept time:** the timeline's time, with deleted stretches of the recording left out. Modifiers are stored in recording time and shown in kept time, so they stay on their footage. Deleting or trimming footage shrinks the modifiers on it, and removes any with under 0.5s left.
- **Time map** (`timeMap` in `clips.ts`): the one place that converts between recording time, kept time (cuts left out) and output time (speed applied), built from the clips and speed regions. The timeline, playback (`useTimeMap` plays at the speed region's rate and skips cuts) and the editor's edits all read it, so no caller converts by hand. The Stage and export both put click rings in output time.
- **Modifier** (`Region` in code): a stretch of time that changes the video, like a zoom or a speed change. Each type is one entry in `REGIONS` (label, key, hue, default length, settings), and its key adds one at the playhead. Each type has a status that groups the Add menu: Modifiers (Zoom, Speed) and Coming soon (Captions, Annotation, Blur, Highlight, Title card), always greyed out in the menu, with no settings or keys until they're built. Audio was removed as a type (Oct 24) and Click ring (Oct 25, now Cursor → Clicks); a saved project drops any type that no longer exists.
- **Suggestion** (`isSuggested` on a region, `SUGGESTIONS` in `regions.ts`): a Zoom or Speed block the app adds on its own, once per recording (`suggest`, flagged by `suggestionsMade` in the project file). Auto zoom comes from bursts of left clicks under 3s apart (`suggestedZooms`): it aims at the first click and pans to each later one (`path`, read by `zoomAt`, so the stage and export both pan). Typing comes from key-press marks in the cursor log, stretches of at least 3s (`typingStretches`); each gets a 2× Speed suggestion (`suggestedSpeeds`) and also counts as a zoom moment. Where the typing is comes from the video, not the keyboard: `typing_spots` (`export/typing.rs`) samples each stretch twice a second at 320px wide and finds the busiest changed area (16px cells; ignoring frames where over 15% changed), so other things changing on screen don't pull it off; lone flicker spots far from the two spots on each side are dropped (`steadySpots`). The zoom aims at the first spot and pans as the text moves; with no spots it aims at the last click or the mouse. For every zoom, a pan is kept only if the aimed view moves at least 8% (`MIN_PAN_SHARE`), so edge repeats and tiny moves don't jitter. Between pans the view follows the moving cursor (`zoomPath`): a zoom whose Focus is Follow cursor (every suggested zoom; a manual one starts on Fixed point) works like Screen Studio: the moving cursor's positions are grouped into a box, and the view aims at the box's middle. It holds still while the cursor stays inside the box and glides only when the cursor outgrows it (wider than half the zoomed view or taller than 70%), then a new box starts. Glides use Screen Studio's spring (stiffness 200, damping 40, mass 2.25) behind a 200ms ease so they start gently, and read the cursor 300ms ahead so a fast cursor stays in frame. Click and typing pans start 750ms early so they arrive with the moment, and start a new box. The cursor only counts as moving once it travels 2% in 300ms, so a resting hand never shakes the view, and while typing (from 1.5s before to 1.5s after a typing stretch) the cursor is ignored so the view stays on the text. It follows in recording time through speed changes, and the export's zoom track comes from the same function. None of these numbers were tuned to a particular clip. It works like any block, drawn as a dashed ghost with a ✓ (keep, `settleSuggestion`) and an ✕ (remove), and its question shows on hover. As it narrows (`suggestionContent`) it drops the name, then the buttons; at icon size the ✓ and ✕ open in a small pill below it on hover or select. Normal blocks hide their grips at icon size (still draggable).
- **Lane:** one row per modifier type in use, in registry order, under the Recording track. A block only moves in time inside its lane. Lanes can be soloed (other types dim, and the stage shows only that type) or collapsed to thin bars.
- **No same-type overlap** (Aidan, Oct 24): two blocks of one type never overlap. A drag stops at a neighbor and jumps past it once nearer the far side, a stretch stops at it, and adding inside one lands in the nearest free gap. Different types overlap freely.
- **Winner:** where two modifiers of one type still overlap (older projects), the later start wins. The lane's gutter and the stage's In effect chips show the winner at the playhead, and the covered part of the earlier block is striped.
- **Project file** (`project.json`): the edits, saved next to the video after every change, with a version, so a crash doesn't lose them; it goes when the recording closes. Older files fill in what they lack.
- **Frame layout** (`frameLayout` in `lib/editor/appearance.ts`): where the recording, corners, shadow and border sit on the canvas. The frame takes the Background panel's **Size** (Auto matches the recording; 16:9, 9:16, 1:1 and 4:5 letterbox it inside the padding). A shape other than Auto also offers **Letterbox** or **Fill** (`fit`; older projects load as Letterbox). **Fill** crops the recording to the padded frame's shape (`frameCrop`, how many times the letterboxed recording the frame is, per side) so a wide recording fills a phone-shaped frame. It works as a floor on the zoom: the scale is never below the one that fills the frame, a Zoom block zooms further by its amount, and outside zoom blocks the view follows the cursor with the same box and spring as a Follow cursor zoom (and aims at the typing spots while typing), so the action stays in view. The view is always kept on the recording, so the background never shows inside the frame. The stage and export share it through `zoomPath`, so they match. While a zoom's focus is being dragged, the stage shows the whole recording and the focus box marks the area Fill will show. The stage combines it with the eased zoom (`zoomAt`) at the playhead; export gets the same numbers through `exportLayout` and the zoom track.
- **Island:** one of the editor's rounded areas, such as the stage and the timeline.
- **Sound** (`SoundSettings` in `lib/editor/sound.ts`, `project.sound`): the recording's volume for the whole clip: one slider per sound track (Microphone, System audio) and Mute. Capture writes system audio as a stereo track and the microphone as a mono one, so `sound_tracks` (`export/mod.rs`) tells them apart by channel count, and the Sound panel shows only the tracks the recording has, or says it has none. Export mixes each track at its volume (`AVAudioMix`) and leaves out a track at 0; muted exports have no sound track. The stage can't set a volume per track (`<video>` has one volume), so it turns off a track at 0 and plays the rest at the louder volume (`stageSound`); with one track it matches the export. Save and Copy from the preview don't use it, like every other edit. Not the speaker button in the timeline toolbar, which only quiets playback.
- **Rail:** the column of icons at the left of the side island. Its top tabs switch the panel (Background, Cursor, Sound); its bottom tabs are app-wide (shortcuts, GitHub, greyed until the repo is public, and Settings).
- **Panel:** what the rail shows beside it: one effect's settings, in sections of field rows.
- **Export settings** (`ExportSettings`): format, frame rate, resolution, quality and where the export goes. The Export button's chevron opens them; the button itself exports with them.

## Shared pieces

- **Pill** (`Pill`): the rounded bar shape every bar in the app uses.
- **Morph pill** (`MorphPill`): a pill that glides between states of different widths, like the record bar's setup and recording states, or the clip dock. Each state keeps its own GPU layer so its text never shakes.
- **Glass:** the native frosted view behind the record bar and the capture bar, owned by Rust in `macos/glass.rs`. A page can only blur its own content, so the blur of the apps behind is native.
- **Panel:** a non-activating macOS panel (`NSPanel`). The bar, overlays and preview are panels, so they float over every space, including full-screen apps, without taking focus. Closing one crashes, so they're hidden, never closed. In the editor, "panel" will also mean a rail section like Background.
- **Floating windows** (`windows/floating.rs`): the record bar and the recording preview. They follow you to the display you click on. One module shows, hides and places them and runs their pointer loop; each window only says what to do when the pointer moves.
- **Pointer hover** (`usePointerHover`): how hover works in windows that get no mouse moves (the preview and the overlays). Rust reports the pointer, and the page marks the element under it with `data-hovered`, which every `hover:` style matches too. This is what "hover bridge" refers to.
- **System-wide keys** (`KeySet`): keys the app takes for a while because its windows aren't focused. Each key set handles its own keys. The picker takes Esc, Return and Tab (`PickerKey`), and Return and Tab go to every overlay: the one holding the Area box acts, or else the one under the pointer. The preview takes E, ⌘C and ⌘S (`PreviewKey`) while the pointer is over it.
- **Own windows:** this app's windows (the record bar, the overlays, the preview, the frame and alerts). Captures always leave them out. Display and area captures leave out the whole app, so windows opened mid-recording stay out too.
- **Cursor log** (`capture/cursor_log.rs`): the cursor position and mouse buttons, polled during a recording and written as JSON Lines next to the video. Polling needs no permission. The editor will use it for cursor and click zooms.
- **Bindings** (`src/lib/bindings.ts`): TypeScript types generated from the Rust types by ts-rs. Don't edit them; run `bun run bindings`.
- **Page event** (`PageEvent`, `lib.rs`): every event Rust sends the pages, with what each carries. It's in the bindings, so a page that expects the wrong payload fails to compile.
- **Rust value** (`useRustValue`): a value Rust owns, like the recording status. A page asks for it once, then follows its event, and the first answer never overwrites a newer event.
- **App storage:** `~/Library/Application Support/com.aidankmcalister.screen-recorder/recordings/`, a hidden scratch folder holding only the open recording, named `YYYY-MM-DD HH.MM.SS`, with its `project.json`. A folder left there at launch means the app crashed: `recover` opens the newest in the preview and deletes the rest. Dev copies (`dev:editor`, named after their source) are left alone, and `dev:editor` skips recovery.
